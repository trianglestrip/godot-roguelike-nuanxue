# 万剑肉鸽 · 剑阵系统 — 完整开发计划

> **Godot 4.6 · PC 桌面（Windows/Linux）· 2D TopDown**  
> 目标：核心可跑、手感爽快、易扩展；**1000+ 敌人场景下可接受**、**同屏约 100+ 飞剑不炸性能**（通过池化与降频检测达成）。

---

## 一、项目定位

| 项 | 内容 |
|----|------|
| 引擎 | Godot 4.6 |
| 平台 | 桌面 |
| 视角 | 2D 俯视角 |
| 风格 | 剑气特效、割草流畅、局内肉鸽成长 |
| 核心 | 剑阵环绕、飞剑自动攻击、剑意能量、随机技能 |

### 计划评审要点（骨架已可落地）

- **目标明确**：千人级敌人场景、同屏大量飞剑的指标直接约束池化与降频检测，降低后期推翻式重构概率。  
- **分层清晰**：架构 → 剑阵 → 技能 → 关卡 → 优化，阶段交付明确，便于迭代。  
- **性能意识**：渲染项、对象池、ShapeCast2D 降频、敌人 AI 降频等与「割草流畅」强相关。  
- **可扩展**：技能基类 + Modifier、数据驱动（JSON/CSV），便于策划与后续内容堆量。  

> 实施策略：**先做出可玩最小原型**（环绕剑阵 + 少量飞剑 + 简单敌人 + 剑意），手感与帧率跑通后再扩内容/美术，正反馈最快。

## 三、阶段 1：基础架构（约 1 天）

- **Rendering → Clustering**：On

## 四、阶段 2：剑阵核心（约 2 天）【最高优先级】

### 1. 飞剑对象池（必做）

```gdscript
# Game.gd 示例
func _ready():
    enemy_pool = ObjectPool.new(preload("res://Enemies/EnemyBase.tscn"), 200)
    sword_pool = ObjectPool.new(preload("res://SwordArray/Sword.tscn"), 128)
```

#### 池子实现要点（落地）

- **API**：`get()` 取出节点，`release()` 归还；归库前必须 `reset()`（位置、速度、角速度、碰撞层/掩码、可见性、`monitoring` 等按需恢复）。  
- **预创建**：池启动时按容量 `instantiate` 好子节点，运行时热路径避免再 `instantiate`。  
- **挂载**：用专用 `Node` 作池容器，子节点为池中实例；取出时 `remove_child` 挂到场景目标父节点，归还时再挂回池容器，**注意**父节点切换时机，避免无意义的全树重排抖动。  

**桌面端经验安全线（可按机器再调）：**

- 同屏飞剑 ≤ **128**  
- 同屏敌人 ≤ **300**  

### 2. `SwordArray.gd`：三种剑阵形态

1. **环绕剑阵（默认）**  
   - 飞剑绕玩家圆周运动  
   - 自动索敌  
   - 可挡子弹（层与碰撞策略在实现时定）  

2. **地刺剑阵**  
   - 范围插剑：AOE + 减速  

3. **万剑归宗**  
   - 全屏爆发，消耗剑意  

### 3. 飞剑运动与命中（高性能约定）

- **环绕运动**：每把飞剑维护轨道角 `angle += orbit_speed * delta`，位置相对玩家极坐标展开；可为每剑缓存独立目标，或由剑阵管理器统一分配。  
- **索敌**：可用 `Area2D` + `body_entered` 维护「邻域敌人列表」，但**飞剑本体不要每帧扫全图**；由 `SwordArray` **每 4 帧**做一次集中分配 / **ShapeCast2D** 校验更符合预算。  
- 进入敌人有效范围后再结算伤害  

### 4. 伤害节奏

- 不对单把飞剑每帧连续扣血  
- **0.2～0.3 s**：可为每剑记录 `last_damage_time`，在 `_process` 中到间隔再结算，避免「全体 Timer 风暴」又避免每帧伤害  
- 必要时 **`call_deferred`** 分摊一帧内集中逻辑  

### 5. 剑意系统

| | 说明 |
|--|------|
| 变量 | `sword_charge` / `max_charge` |
| 获取 | 击杀 +5～15；普攻 +2（数值可数据驱动） |
| 消耗 | 地刺约 −30；万剑归宗约 −100 |

**玩法向扩展**（完美闪避、碎片拾取、衰减、满剑意迸发等）见 **§ 十四、2**。  

建议拆成独立 **`Resource`（如 `SwordEnergy`）** 或清晰子模块：经事件（击杀、命中）增减数值，**发信号**驱动 HUD；剑阵**形态切换**时加简短过渡特效（缩放/Flash/Tween 轨道），手感更清晰。

**形态切换手感**：轨道半径、角速度可用 **`Tween`** 过渡，避免瞬切导致碰撞与视觉抖动。

详细技能与词条与 Modifier 的叠加规则见 **[skills.md](./skills.md)**。

## 六、阶段 4：敌人、波次与关卡（约 1 天）

### 1. 敌人与池

- 尽量不用 `queue_free` 热路径狂删节点  
- `hide()` + `reset()` + `return_to_pool()`  

### 2. AI（轻量）

- 非必要不用 `NavigationAgent2D`  
- `velocity = direction * speed` + `move_and_slide()`  
- **每 8 帧** 更新一次追击/游荡方向  

### 3. 关卡骨架（肉鸽）

- 建议 **5 层**  
- 每层 **4～6** 个房间  
- 房间类型：战斗、奖励（三选一）、商店、BOSS  
- 流程：清怪 → 开门 → 下一房间  

#### 房间与流程（落地）

- **`RoomManager`**（或等价节点）：维护当前房敌人列表；清空后发信号 → 开门、生成奖励/三选一。  
- **加载方式**：优先 **动态实例化房间模板**（`PackedScene.instantiate()`），比整场景 `change_scene` 更贴肉鸽迭代；具体选「子Viewport根」还是「关卡根下换子树」按项目定。  
- **数据**：每房波次、敌种、奖励 ID 等放 **JSON**（`Data/rooms/`），运行时解析，便于策划改表不调代码。  
- **局内进度**：当前层、房间索引、已选技能/词条等，建议集中到一个 **`RunData`（`Resource`）** 序列化或字段拷贝，进新房时读取、出房时写回。

## 七、阶段 5：特效（约 1.5 天）

### 必做方向

1. **飞剑轨迹**：`Line2D` + 渐变 + 透明度；可 **每 2 帧** 更新  
2. **环绕光环**：环形 Shader，随飞剑数量缩放  
3. **地刺**：插剑瞬间粒子 + 轻微屏幕震动  
4. **万剑归宗**：径向收敛 → 爆发感（粒子 + 时间缩放等按需）  
5. **击杀**：闪光、小爆、飘字  

### 性能约定

- 单特效粒子数建议 **≤ 30**  
- 生命周期建议 **≤ 0.5 s**  
- Soft Particles 勿滥用  
- **特效实例同样池化**  

### Shader 方向

- 飞剑发光、拖尾、受击闪、剑阵光环：**先用 `ShaderMaterial` 做最小可用**，再迭代画质；资源放 `Effects/`（本文附录可补路径）。

#### 特效落地细节

- **拖尾**：`Line2D` + `Curve` 渐变，**每 2 帧**更新点列，降低成本。  
- **震屏**：`Camera2D` **offset** + `Tween`/短动画回中，勿在物理步里每帧猛改相机。  
- **粒子**：继续遵守单特效 ≤30、短生命周期；**特效节点同样走对象池**。

## 八、阶段 6：优化清单（约 1 天）

- 飞剑 / 敌人 / 特效 **池化**  
- ShapeCast2D **4 帧** 一次；敌人朝向 **8 帧** 一次  
- 发布构建关闭 `print` 垃圾输出  
- 非必要 `_process` 精简；批量逻辑 `call_deferred`  
- UI 使用 **CanvasLayer** 分离  
- 桌面可开 **MSAA 2x/4x**、关注渲染线程与目标分辨率；固定高帧率按需（如 120）  

### 性能监视（开发期常驻习惯）

- 编辑器 **Debugger → Monitors**：关注 `Objects`、`Nodes`、`Physics 2D FPS`、`Process Time` / `Physics Time`。  
- 开发期可用 `Engine.get_frames_per_second()` 在 Debug HUD 显示帧率；**发布**关掉冗余 `print`，必要时 `--verbose` 仅用于本地查问题。

可与上文「阶段 1～7」并行参照；以**周**为单位更贴独立开发节奏。

| 周次 | 重点 | 交付自检 |
|------|------|----------|
| **第 1 周** | `Game.gd` + 对象池骨架；玩家 `CharacterBody2D` 移动 + 闪避；**环绕剑阵约 5 把飞剑** + 约 **0.3 s** 伤害节奏；1 种池化追击敌人 | 可玩循环、剑意可涨 |

| **第 4 周** | 特效池、拖尾/击杀闪/光环；基础音效；`call_deferred` 与池回收巡检；**首个可对外试玩包** | 长时间打打不漏池、不叠节点 |

## 十一、风险与对策

| 风险 | 对策 |
|------|------|
| 同屏飞剑多 **渲染** 吃紧 | 屏外 `visible = false`；.sprite 降分辨率；同屏上限 + LOD 视效 |
| 形态切换 **碰撞/轨道** 突跳 | `Tween` 过渡半径与角速度；短时间无敌/伤害窗口与策划对齐 |
| Modifier 过重 **设计/调试** 困难 | **第一期**先做「属性修改 + 信号改 `SwordArray` 全局倍率」，再升级为完整 Modifier 栈 |
| 敌人多 **物理/AI** 飙升 | 保持 **8 帧**转向；远距离敌人更长间隔更新；超阈值时削减远端 AI 频率 |
| 肉鸽 **进度/读档** 混乱 | 单 **`RunData` Resource** 权威；进房拷贝、关键节点存档点明确 |

## 十二、工程补充建议

- **输入**：`InputMap` 配置移动、闪避、剑阵技能；有余力做手柄映射。  
- **UI**：HUD（血条、剑意、升级）**全部 `CanvasLayer`**，与游戏节点解耦、少受相机缩放牵连。  
- **音频**：独立 **`AudioManager`**（或等价单例），**池化** `AudioStreamPlayer2D` / `AudioStreamPlayer`，避免高频 `instantiate`。  
- **导出**：发布包关闭 **Export With Debug**；在目标机上再跑一遍 Monitors 与长时间战斗。

## 十四、玩法与体验设计（深度 · 节奏 · 重玩）

> 技术路线见上文阶段 1～7；本章补齐 **「好玩、上瘾、有策略」** 的产品向约束，与 **[skills.md](./skills.md)** 中的词条维度、稀有度、流派相互引用。

### 1. 剑阵形态差异化（每种要有独立定位）

| 形态 | 核心玩法 | 爽点 | 策略价值 |
|------|----------|------|----------|
| **环绕剑阵（默认）** | 飞剑绕体、自动索敌、可挡弹幕 | 稳定输出、攻防一体 | 万金油；剑意获取与探索期手感基线 |
| **地刺剑阵** | 周身插剑、持续范围伤 + 减速 | 范围压制、强控场 | 被包围时清场；飞剑暂离环绕、**防御面下降**，需权衡 |
| **万剑归宗** | 全屏汇聚后爆发 | 瞬清杂兵、视觉高潮 | 高剑意消耗；适合精英/BOSS 或翻盘；可设计**满剑意**才解锁以防滥用 |

- **形态切换成本**：短 **CD** 或小额 **剑意**，迫使玩家在战况中做时机判断（与阶段 2 中 Tween 过渡一致）。  
- **可扩展形态（肉鸽解锁）**：在性能与池容量允许下逐步加入，例如：**护体剑盾**（高速回旋、偏转投射物、压低主动索敌）、**追踪剑雨**（升空追踪标记目标）、**剑气风暴**（环形向外推扩 + 伤害波）。实现上均为 `SwordArray` 的 **姿态/状态机** + 数据驱动参数。

### 2. 剑意：不仅是条，更是行为驱动

**获取（鼓励进取）：**

- 击杀（基础）、**完美闪避**、拾取 **剑意碎片**（鼓励走位）、暴击/词条追加等（具体 Modifier 见 skills.md）。

**消耗（决策点）：**

- 形态切换（小消）、某形态下**持续耗剑意换强化**（如短时加环绕飞剑数）、终极技（万剑归宗）大包。  

**风险与窗口（防龟缩）：**

- 可设计**随时间微衰减**，逼迫接敌。  
- **满剑意特殊状态**（例：「剑意迸发」）：短窗内全形态强化 → 结束后**清空或大扣**，形成「攒满打一波」的明确爽点（数值与 VFX 需与性能预算对齐）。

### 3. 战斗节奏与敌人设计

**类型建议：** 近战海（割草）/ **远程**（逼走位或挡弹）/ **重装**（适合地刺减速集火）/ **召唤师**（优先处理）/ **精英·BOSS**（阶段、护盾、反制剑阵的技能）。  

**与剑阵互动：**

- 击飞飞剑、短时降低可用剑数；**封印区**内飞剑失效逼走位；死亡掉落**需拾取**的剑意结晶（风险换资源）。  

**难度与喘息：**

- 层数↑敌人强度↑，与局内成长曲线匹配；战斗 / 奖励 / 商店交替；**BOSS 前安全屋**（回复或免费三选一）降低挫败感。与本文 **「六、阶段 4」** 房间骨架一致。

### 4. 局外成长（Meta Progression）

- **剑谱 / 图鉴式解锁**：消耗局内金币或「剑魂」解锁新形态、新初始词条、扩充奖励池（注意**不**做成纯数值碾压局内）。  
- **天赋树**：小额永久加成（例：初始飞剑 +1、剑意衰减慢），上限封顶以保持局内随机性。  
- **成就**：挑战解锁外观或**非破坏平衡**的新选项层。  

局外目标：**更多构建选择与主题**，而非单局必赢。

### 5. 手感与主题包装

- **打击反馈**：受击闪、轻击退、命中亮刃、飘字、分层音效（飞剑出/中/剑意涨跌/切形态）。  
- **连击**：连击阈值触发短时剑意加成或增益，强化「不停手」的心流（注意 UI 与音效别过载）。  
- **震屏**：限定在暴击、精英/BOSS 击杀、大招，避免廉价化。  
- **美术与命名**：水墨仙侠/剑气等主题与 UI（卷轴、剑形图标、剑谱）统一；技能命名可强化代入（如御剑诀、天罡剑阵等），与 `Data/` 文案表一致。

### 6. 经济与资源循环（局内）

- **金币**：商店买词条/升级/回血；高价核心装 vs 即时战力需要权衡。  
- **剑意**：调节**敢不敢切形态、敢不敢开大**的节奏轴。  
- **生命**：有限回复点，抬高风险意识。

**流派协同（构建深度）**见 **[skills.md § 十一](./skills.md#十一流派与协同重玩性)**：飞剑数量流、暴击流、剑意爆发流、地刺控场流、防御反击流等；词条组合应能指向不同 Synergy，避免全场唯一最优解。
